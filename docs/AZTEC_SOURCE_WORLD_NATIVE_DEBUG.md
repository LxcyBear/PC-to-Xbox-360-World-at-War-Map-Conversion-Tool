The Xbox diagnostic assembled on 2026-10-30 with `Stage-AztecFirstExceptionCanary.ps1` contained a small structurally valid main.ff and converted original-PC-selected load.ff. It was deliberately NOT a converted Aztec world. User's size observation prompted prioritizing the physically larger, original-PC-derived 8,509-root GfxWorld world FF. The previous canary is retained as an independent regression artifact, not overwritten.

Source world report: `output/second_map_baselines/nazi_zombie_aztec_V2.2/native_material_mapping/pc_gate8_29x_ff/aztec_pc_world_core_integrated_oat_run.json`. Historical OAT-validated world FF: exactly 3,615,230 B, SHA-256 `0CBD019ABB5D702429B9EECA9B04A843311FF118DDEDBD5CF012C757F757CF82`. Includes 28 converted XModels, 735 source GfxSurfaces, 39 real Materials, 32,713 original-PC vertices/58,653 indices, and a partially reconstructed GfxWorld. No live GfxWorld static draw record pointers (0/1903), incomplete DPVS/cells/lightmaps/image ownership/runtime script/weapon closure. **DO NOT describe as a full converted Aztec map**. 9/13 progress counts evidence, not finished conversion percentage.

Existing genuine PC2XB3 `_load.ff` is from the prior independent native debug stage generated by `aztec-native-test-load-emit` (7-node typed converter); main+load provenance and SHA are recorded in `output/native_debug_stage/aztec_first_exception_20261030_183049_d55704c9/PROVENANCE_NATIVE_DEBUG_NOT_RELEASE.json`. Its verified SHA-256 is `DEA45B360514473C7B3E769DABBA0ED7A0538FCDC06DD508B52CB845136FFDCE`; 363,952 bytes. The load emitter reports a stock defeat-reference donor; this **is not zero-donor production**.

## Run, from repo root, on xbox360/aztec-two-xmodel-diagnostic

```powershell
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File '.\tools\oat-xenon\Test-WaWMultiMapScriptSyntax.ps1'
powershell -NoProfile -ExecutionPolicy Bypass -File '.\tools\oat-xenon\Stage-AztecWorldFirstExceptionCanary.ps1'
powershell -NoProfile -ExecutionPolicy Bypass -File '.\tools\oat-xenon\Stage-AztecWorldFirstExceptionCanary.ps1' -Stage
```

The second command is **read-only preflight**. The `-Stage` command does NOT compile, rebuild, repair or overwrite any FF. It verifies the exact historical world SHA, emitter manifest and 28/735/39 source graph evidence, verifies the existing converted _load.ff + original-PC source chain, then independently runs native Xenon OAT List and Extract on **both** FFs. If even one validation fails, NO complete stage is produced. A unique `output/native_world_debug_stage/aztec_world_first_exception_.../_codxe/usermaps/nazi_zombie_aztec/` is created for this one native first-exception experiment; its provenance manifest lives OUTSIDE the console-visible map directory.

Expected small file set: `nazi_zombie_aztec.ff` (3,615,230 B), `nazi_zombie_aztec_load.ff` (363,952 B), optional `mod.arena` metadata from earlier stage. NO native-reference FFs, no fabricated/borrowed `_patch.ff`, `.pak`, videos, sound files, highmips, `preview.dds`, or unrealized map-world dependency graphs.

This is an **opt-in native debug probe** only: missing assets may cause return-to-menu or exceptions, potentially before map initialization. Keep the **strict production release gate** `Approve-AztecNativeSmokeTest.ps1` unchanged and blocked until full DPVS/draw/dependencies are truly integrated. Never assert full gameplay or Xbox readiness from OAT List/Extract alone.

## Console test and immutable proof

Back up the existing `/_codxe/usermaps/nazi_zombie_aztec/` map folder away from the active usermaps directory before replacing it. Do not merge old known-good reference FFs with these generated FFs. Confirm CodXe's expected flat `_codxe/usermaps/<map>/` root for the installed beta; menu metadata from a reference may be used as metadata only and must be accounted for by hash. Copy the new generated map folder contents into a clean console folder. Start WV first-exception context + xbWatson, launch once, record first exception/call stack and furthest stage. Some CodXe builds use alternate content roots, so confirm actual file-open path in the plugin log.

Use a mounted/read-back Xbox directory to verify exact bytes, not a local stage path:

```powershell
$m='C:\Full\Path\To\PROVENANCE_SOURCE_WORLD_NOT_RELEASE.json'
$x='C:\Folder\CopiedBackFromXbox\nazi_zombie_aztec'
powershell -NoProfile -ExecutionPolicy Bypass -File '.\tools\oat-xenon\Verify-AztecWorldXboxCopiedFFs.ps1' -ManifestJson $m -XboxCopiedMapDirectory $x
```

A hardware boot/return is meaningful only if both installed-source SHA-256 values are matched. The capture distinguishes early FF loading from runtime world/weapon/script faults. We do NOT infer missing assets from a raw exception address alone, and we retain exact CodXe / Title Update versions and all logs.
